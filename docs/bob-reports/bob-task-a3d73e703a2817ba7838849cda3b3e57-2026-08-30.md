# GOAL

Extend ReleaseGuard so it can reliably detect, execute, parse, analyze, and gate releases for:

1. Python
2. Node.js
3. Java
4. Rust

Python support must remain fully functional. Do not remove or regress existing Python functionality.

ReleaseGuard must follow this architecture:

CLONE
  ↓
DETECT PROJECT
  ↓
LOCATE PROJECT ROOT
  ↓
SELECT TEST COMMAND
  ↓
EXECUTE TESTS IN CORRECT WORKING DIRECTORY
  ↓
PARSE TEST RESULTS
  ↓
CREATE TestRunResult
  ↓
ANALYZE FINDINGS
  ↓
MAKE SAFE RELEASE DECISION

============================================================

Implement a clean deterministic architecture for language-specific test support.

Use the existing project architecture where possible. Do not duplicate unrelated logic.

Create or extend language-specific support so each language has deterministic handling for:

- project detection
- project root location
- test command selection
- test execution
- output parsing

The implementation should support a structure conceptually similar to:

releaseguard/

    tests/

Do not force this exact folder structure if the existing architecture already has suitable modules. Integrate cleanly with the current codebase.

============================================================
3. NODE.JS SUPPORT
============================================================

Add complete Node.js project support.

Detect Node.js projects using:

- package.json

Locate the directory containing package.json and use it as the project root.

IMPORTANT:

Never execute npm test from the ReleaseGuard application root unless that root itself contains the detected package.json.

Before running tests:

1. Read package.json safely.
2. Check whether a scripts.test command exists.
3. If no test script exists, create an appropriate HIGH severity tooling/testing finding instead of pretending tests passed.
4. Execute npm test using cwd equal to the detected Node project root.

Capture:

- stdout
- stderr
- exit code
- execution errors

Support deterministic parsing for common output formats including:

Jest examples:
Tests:       5 passed, 5 total
Tests:       2 failed, 3 passed, 5 total

Mocha examples:
  5 passing
  2 failing

Generic npm failures should still be represented correctly even when exact totals cannot be parsed.

If npm test succeeds but test counts cannot be determined:

- total must remain None or explicitly unknown
- ReleaseGuard must NOT approve the release
- create a HIGH severity finding explaining that test execution could not be verified

4. JAVA SUPPORT
============================================================

Add deterministic Java project support.

Detect Maven projects using:

- pom.xml

Detect Gradle projects using:

- build.gradle
- build.gradle.kts

Prefer commands deterministically:

gradlew.bat test

System Gradle fallback:
gradle test

Do not run a command if the required build tool cannot be located without reporting a tooling finding.

Capture:

- stdout
- stderr
- exit code
- execution errors

Parse common test summaries.

Maven examples:

Tests run: 10, Failures: 0, Errors: 0, Skipped: 0

Gradle examples:

10 tests completed, 0 failed

Correctly calculate:

- total
- passed when determinable
- failed
- skipped when available

If tests cannot be verified, the release must not be approved.

- skipped/ignored when supported by the model

============================================================
8. SAFE ANALYZER RULES
============================================================

Update analyzer behavior so ReleaseGuard distinguishes:

CASE A:
Tests ran successfully and total > 0

CASE B:
Tests ran successfully and total == 0

CASE C:
Command succeeded but total == None

CASE D:
Command failed

Required behavior:

CASE A:
Normal analysis.

CASE B:
Create HIGH severity TESTING finding:
"No tests found"

CASE C:
Create HIGH severity TESTING finding:
"Could not verify test execution"

CASE D:
Create HIGH severity TOOLING or FUNCTIONAL finding depending on evidence.

Never silently treat unknown tests as zero tests.

Never silently treat zero tests as successful release evidence.


============================================================
9. SAFE RELEASE DECISION
============================================================

Fix the release decision logic.

A release may be approved only when ALL applicable conditions are satisfied:

1. At least one project was successfully tested.
2. At least one test was successfully discovered overall.
3. Total discovered tests > 0.
4. No failed tests.
5. No execution errors.
6. No unavailable required tooling that prevents verification.
7. No BLOCKER findings.
8. No HIGH severity release-blocking findings.
9. Test evidence is trustworthy.

Conceptually:

release_ready = (
    total_tests > 0
    and total_failed == 0
    and no_execution_errors
    and no_unverified_test_runs
    and no_release_blocking_findings
)

This must prevent the unsafe state:

Tests: 0
Passed: 0
Failed: 0

RELEASE READY

That result is incorrect and must never occur.

def _check_node_test_script(cwd: Path) -> str | None:
    """Return an error reason string if package.json has no test script.

    Returns None when a test script is present or package.json cannot be read
    (in that case we let npm fail naturally so the error is captured).
    Returns a non-empty string when the test script is explicitly absent —
    this prevents running ``npm test`` which would exit non-zero with a
    misleading "missing script: test" error that could be mistaken for a
    real test failure.
    """
    pkg = cwd / "package.json"

    if not pkg.exists():
        return None  # no package.json here; let npm fail naturally

    try:
        data = json.loads(pkg.read_text(encoding="utf-8", errors="replace"))
    except (json.JSONDecodeError, OSError):
        return None  # unreadable; let npm fail naturally

    scripts = data.get("scripts", {})

    if not isinstance(scripts, dict):
        return "package.json scripts field is not a mapping"

    if "test" not in scripts:
        return (
            "package.json has no 'scripts.test' command — "
            "no test suite is configured for this Node.js project"
        )

    test_script = scripts["test"]
    if isinstance(test_script, str) and test_script.strip().lower() in (
        "echo \"error: no test specified\" && exit 1",
        "echo 'error: no test specified' && exit 1",
        "echo \"error: no test specified\"",
    ):
        return (
            "package.json 'scripts.test' is the npm placeholder — "
            "no real test suite is configured"
        )

    return None

    skipped: int | None = None,
    execution_error: str | None = None,
    unavailable_reason: str | None = None,
) -> TestRunResult:
    return TestRunResult(
        project=_proj(lang),
        command="test",
        exit_code=exit_code,
        stdout=stdout,
        stderr=stderr,
        duration_seconds=0.1,
        total=total,
        passed=passed,
        failed=failed,
        skipped=skipped,
        execution_error=execution_error,
        unavailable_reason=unavailable_reason,
    )


def _make_repo(tmp_path: Path, files: dict[str, str]) -> Path:
    """Create a temp repo with given relative-path -> content mapping."""
    for rel, content in files.items():
        p = tmp_path / rel
        p.parent.mkdir(parents=True, exist_ok=True)
        p.write_text(content)
    return tmp_path
